# Languages

The interface is available in German, English, French and Spanish. German is the
reference language: its message file defines the shape every other language has to
follow, so a missing or misspelt key fails the type check (and with it the CI).

## How the language is chosen

1. The `lang` cookie, set when someone picks a language (sign-in page or menu).
2. Otherwise the browser's `Accept-Language` header.
3. Otherwise German.

Pages with `getServerSideProps` resolve the language on the server
(`src/i18n/server.ts`) and render in it right away, so nothing flickers after
loading. URLs do not change with the language.

## Where things live

| Path | Contents |
| --- | --- |
| `app/src/i18n/locales.ts` | Supported languages, names for the switcher, Intl tags, `Accept-Language` parsing |
| `app/src/i18n/messages/de.ts` | German texts; defines the `Messages` type |
| `app/src/i18n/messages/{en,fr,es}.ts` | The other languages, typed as `Messages` |
| `app/src/i18n/I18nProvider.tsx` | React context: `const { t, locale, setLocale } = useI18n()` |
| `app/src/i18n/errors.ts` | Turns `EditError`/`UploadError` codes into text |
| `app/src/i18n/countries.ts` | Country suggestions via `Intl.DisplayNames` |
| `app/src/family/kinship/words/` | Kinship terms and sentence building per language |

## Writing texts

- Components read texts from `t`, e.g. `t.person.edit`. Texts with values are
  functions: `t.relative.added(name)`, `t.views.people(count)`.
- Plain functions outside React (dates, birthdays, calendar, kinship) take a
  `locale` parameter that defaults to German.
- Dates, month names, "today/tomorrow" and country names come from `Intl`, so
  they follow the language without extra texts.
- In the German file, a function whose result is one of two fixed strings needs an
  explicit `: string` return type. Otherwise TypeScript infers exactly those two
  strings and the other languages cannot return anything else.

## Kinship terms

`app/src/family/kinship/index.ts` computes a language-neutral relation, for example
`{ kind: 'cousin', degree: 2, removed: 1 }`. Each file in `words/` turns that into
a term ("second cousin", "once removed"), a label from the reader's point of view
("Your second cousin, once removed"), a heading and a full sentence. Grammar such
as German genitive, French elision (`l’oncle`, `d’Anton`) or Spanish contractions
(`del hermano`) is handled there.

## Kept in German on purpose

The calendar route `/api/kalender/…` and its query parameters (`linie`,
`vorfahren`, `nachkommen`, `seiten`): existing subscriptions use them. The optional
`lang` parameter selects the language of the event texts; links without it stay
German.

## Adding a language

1. Add the code to `LOCALES`, `LOCALE_NAMES` and `INTL_TAG` in `locales.ts`.
2. Copy `messages/en.ts` to `messages/<code>.ts`, translate it and register it in
   `messages/index.ts`.
3. Add `kinship/words/<code>.ts` implementing `KinshipWords` and register it in
   `kinship/words/index.ts`.
4. Add a few kinship expectations to `src/__tests__/family.test.ts`
   ("kinship in other languages").
5. `npm run typecheck` lists every key that is still missing.
